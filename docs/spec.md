# 防災ハブ 設計書

最終更新: 2026-07-31

## 1. 概要

大規模災害時に「どのアプリ・どのページを見ればいいか」で迷わないようにするための、カテゴリ別リンク集約型のランチャーアプリ。

**このアプリ自体は防災データを持たない・生成しない。** 既存の信頼できる防災系サービス(NERV防災、Yahoo!防災速報、電力会社の停電情報、国の公的発表ページなど)への「入口」を整理して1箇所にまとめるだけの構成。これにより、外部データ取得・可用性・誤情報のリスクを避け、実装をシンプルに保つ。

きっかけ: 2026年7月28日発生の熊本県熊本地方 M7.1・最大震度7の地震(宇城市・氷川町)。

## 2. 対象ユーザー・UI方針

- **老若男女、高齢者や操作に不慣れな人でも直感的に使えること**が最重要要件
- 大きな文字・大きなタップ領域・高コントラスト・シンプルな線のアイコン・最小限のテキスト・広めの余白
- 写真調ではなくベクター調のフラットUI(装飾より視認性・タップしやすさを優先)

## 3. アプリ形態

- **PWA**(スマホのホーム画面に追加できる形)
- 単一HTMLファイル(HTML/CSS/JS内包) + `manifest.json` + Service Worker(オフラインでも画面自体は表示できるようキャッシュ)
- バックエンドなし。地域選択などの状態は `localStorage` に保存し、次回起動時に自動反映
- ホスティングは GitHub Pages(無料枠)

## 4. 画面構成

### 4-1. トップ画面
- ヘッダー: アプリ名「防災ハブ」(左) + 現在地域表示(右、例:「熊本県」)
- 災害種別トグル(手動選択、4つの大きなチップ): 「地震」「大雨・洪水」「停電」「断水」
  - タップした災害種別に対応するカテゴリカードが**一番上に移動し、赤枠で強調表示**される
  - 外部データ取得は行わない(利用者が今の状況を自分で選ぶだけ。オフラインでも確実に動作する)
- カテゴリカード一覧(下記6.のカテゴリ。アイコン+タイトル+短いサブタイトル+タップで詳細画面へ)
- フッター: 「地域を変更」ボタン

### 4-2. カテゴリ詳細画面
- 戻る矢印 + カテゴリ名
- 「開くアプリを選んでください」
- カテゴリ内の子アプリ/リンクを大きなカードで縦に並べる。タップで該当の公式URLへ遷移(7.の仕組み参照)

### 4-3. 地域を変更画面
- 戻る矢印 + 「地域を変更」
- 都道府県検索ボックス + 都道府県リスト(選択中の県は赤背景+チェックマーク)
- 「決定」ボタンで確定 → `localStorage` に保存 → 以後トップ画面・各リンクに自動反映

参考画像: `docs/mockup-top.png`(トップ画面) / `docs/mockup-detail-region.png`(①カテゴリ詳細画面 ②地域変更画面)

## 5. ★リンク設計の最重要原則: 恒久リンクと災害別リンクの区別

**このアプリの寿命を左右する設計判断。** 公的機関の災害情報ページには2種類ある。

| 種類 | 例 | 扱い |
|---|---|---|
| **恒久リンク**(常設の入口。常に最新の災害が最上部に並ぶ) | 内閣府防災「災害情報一覧」`bousai.go.jp/updates/`、国交省「災害・防災情報」`mlit.go.jp/saigai/` | **これをアプリに埋め込む。** 次の災害が起きても自動で最新に追従する |
| **災害別リンク**(その災害専用に作られたURL) | 内閣府 `updates/r8kumamoto_jishin/`、経産省 `meti.go.jp/2026_kumamoto/` | **埋め込まない。** 災害ごとにURLが変わるため、次の災害では死にリンクになる |
| **市区町村の生活支援情報**(給水・物資配布) | 熊本市の給水拠点情報など | **埋め込まない。** 全国1,700以上あり維持不能。地域名を使った検索リンクで対応 |

→ 原則: **「常に最新が出てくる入口」だけをハードコードし、それ以外は検索リンクに逃がす。** これにより、アプリを更新しなくても次の災害で機能し続ける。

## 6. カテゴリ構成(確定)

| # | カテゴリ | 内容 | リンク方式 |
|---|---|---|---|
| 1 | 地震・気象速報 | NERV防災 / Yahoo!防災速報 / NHKニュース・防災 / 気象庁 | 全国共通の恒久リンク |
| 2 | 避難所・避難情報 | 選択都道府県の避難所開設情報 | 「選択地域名 + 避難所 開設」の検索リンク |
| 3 | 停電情報 | 選択都道府県に対応する電力会社の停電情報ページ(例: 熊本県→九州電力送配電) | 全国10電力会社の恒久リンクに、都道府県→電力会社の対応表でマッピング |
| 4 | 給水・食料配布 | 選択都道府県の給水拠点・物資配布情報 | 「選択地域名 + 給水 支援物資」の検索リンク |
| 5 | **支援状況・国の対応**(新規) | 内閣府防災「災害情報一覧」/ 国交省「災害・防災情報」 | 恒久リンク(5.参照) |
| 6 | 通信手段(ネットが使えない時) | 00000JAPAN(災害時無料Wi-Fi) / 災害用伝言板web171 / 災害用伝言ダイヤル171 | 全国共通の恒久リンク。**災害種別に関わらず常時表示** |
| 7 | 平常時の備え | 農林水産省「家庭備蓄ポータル」 | 恒久リンク。災害が起きていない時に見る枠として下部に配置 |

### 6-1. カテゴリ5「支援状況・国の対応」の調査結果(2026-07-31 実ページ取得により確認)

利用者から「支援の状況が分かる、随時更新されるリンクを入れたい。農水省が発信しているのか？」という要望を受けて実際に各省庁のページを取得して確認した結果:

- **農林水産省**: 災害情報ページの中身は、被災した農林漁業者向けの**融資・共済・償還猶予**が中心。一般の被災者向けに「今どこで食料が配られているか」といったリアルタイムの支援状況は発信していない。ただし平常時向けの「家庭備蓄ポータル」は有用なので、カテゴリ7として別枠で採用する
- **内閣府(防災担当)**: **ここが本命。** 国が被災自治体の要請を待たずに物資を送る「プッシュ型支援」の実施状況を含む被害状況等を公表している。かつ「災害情報一覧」が恒久リンクとして機能し、最新の災害が常に最上部に並ぶ
- **国土交通省**: 「災害・防災情報」が恒久的なポータルとして機能。道路の被害状況マップ、鉄道各社・空港・航空・旅客船の運行状況、TEC-FORCE(緊急災害対策派遣隊)の派遣状況など、**移動・物流に関する情報**が集約されている
- **都道府県公式ページ**: 熊本県の令和8年熊本地震ページを確認したところ、掲載の中心は相談窓口・義援金受付・健康注意喚起であり、給水拠点や物資配布のリアルタイム情報は含まれていなかった。**給水・物資の実務情報は市区町村レベル**(熊本市など)にあるため、カテゴリ4は検索リンク方式が妥当であることが裏付けられた

## 7. 外部アプリへの遷移の仕組み

各カードは対象サービスの**通常のhttps公式URL**にリンクするだけで、防災ハブ側で特別なディープリンク実装は行わない。

- **インストール済みの場合**: iOS/AndroidのOS標準機能(ユニバーサルリンク/アプリリンク)により、対応済みアプリがあればOSが自動判定し、ブラウザを経由せずアプリが直接開く
- **未インストールの場合**: 通常のWebページが開く(多くの場合そこにアプリストアへの誘導が表示される)
- この挙動は各サービス側の実装に依存する(防災ハブ側でコントロール不可)。ただし主要アプリ(NERV防災・Yahoo!防災速報・NHK等)は概ね対応している

## 8. 災害種別ハイライトの仕組み(確定: 手動選択方式)

- 利用者がトグルで今の状況(地震/大雨・洪水/停電/断水)を選ぶと、対応カテゴリが上部に移動+強調表示される
- 気象庁等の外部データ取得は行わない(自動検知方式は不採用。理由: CORS対応・取得失敗時のフォールバックなど複雑さが増し、単一HTML+GitHub Pagesという軽量構成から外れるため)
- カテゴリ6(通信手段)は災害種別に関係なく常に表示する

## 9. 地域データ

- 都道府県選択(47都道府県)を `localStorage` に保存
- 都道府県 → 電力会社(10社)の対応表を静的データとして保持
- 都道府県名は避難所・給水カテゴリの検索リンク生成にも使用

## 10. セキュリティ・運用方針

- 無料枠のみ(GitHub Pages)。バックエンドなし、ユーザーデータの収集・送信は行わない(全てブラウザのlocalStorageに閉じる)
- GitHubリポジトリはPrivateで作成
- シークレット・APIキー等は使用しない(全て公開情報へのリンクのみのため)
- **00000JAPANの注意書きをアプリ内に明記する**: 緊急時の接続性を優先して暗号化されていないため、ID・パスワード等の重要な通信は避ける旨を、カテゴリ6の画面に短い注意文として表示する

## 11. 実装ステップ

1. GitHubリポジトリ作成(本設計書を格納) — 完了

3. Playwrightでの実機確認(スマホ幅・ホーム画面追加・地域切替保存・災害種別トグル動作)
4. GitHub Pagesへデプロイ
5. コミット&プッシュ、完了報告(公開URL)
